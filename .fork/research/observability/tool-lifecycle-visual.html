Where does a tool call become visible?

A model writing a call, a tool running, and a UI showing the result are three different moments. Pi keeps them connected; bb currently loses information between them.

Read the full cited report for source-by-source evidence. This graphic distinguishes verified behavior from unknown native-UI internals. The protocol direction was later recorded in the linked issue; tool-specific presentation remains an open child decision.

01 / One call, six moments

Name + identity“read” and call ID become known. Not executing yet.
Input buildsPath or arguments arrive; may be incomplete JSON.
Execution startsPermission may intervene before the tool runs.
Partial outputOptional: bash emits; a read may return only at the end.
Final resultText, image, error and metadata can all matter.
View + replayPreview/expand on screen; durable result for reopening.

The key distinction: an unfinished call input is not tool output. A result can be complete even when the tool never streamed progress.

04 / What pi gets right—and what not to copy literally

Stable call identity

One call is updated across input, execution, output and completion. A redraw is not a second tool invocation.

Partial is optional

A tool with no live updates still has a named call and a final result. Don't fake streaming for read/search.

Result ≠ rendering

Retain useful structured content; let generic and specialist renderers choose previews and expansion.

Ephemeral ≠ durable

Transient snapshots need not create one database row each; replay needs an authoritative final record.

Provider-neutral core

Accommodate raw provider payloads, typed blocks and presentation hints; don't encode only pi/bash/read names.

Different transports

Pi mutates a local TUI component; bb crosses bridge, daemon, server and browser. The same UX needs explicit delivery/recovery.

Protocol direction decided; presentation still open

The protocol decision calls for one stable identity, provisional parsed-argument snapshots, optional partial results, and a generic final result. Raw JSON fragments are not required for normal rendering. Tool-specific presentation is a separate decision; none of this assumes every native harness behaves like pi.
